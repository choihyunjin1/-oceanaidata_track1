현재 단계는 **계획만**이다. 이 문서 작성 중 코드 수정, 데이터 값 재분석, 학습, 모델 생성, 제출, commit/push는 하지 않았다. 아래 실행은 사용자가 추론 강도를 낮춘 뒤 진행할 후속 작업이다.

## 1. 결론

새 모델을 더 많이 찾는 것보다 다음 세 가지의 기대 가치가 높다.

1. **P1: 기존 강한 트리 모델을 재사용하여 장기 이상을 표현하고, 기존 오탐도 수정할 수 있게 한다.** 단순 이상 추가, TabPFN 재실행, 무차별 구간 확장은 우선순위에서 내린다.
2. **P2: 실제 복원 작업과 내부 검증을 일치시킨 뒤 v23/v52/OAS를 다시 비교한다.** 지금까지의 작은 개선들이 잘못된 비교 기준을 이긴 것인지 구분한다. 이후 공개층 연속 결측과 목표 실제 수심을 한 축씩 시험한다.
3. **P3: 합법적 기존 예측의 상보성을 먼저 확인하고, 기상 결측 증강 하나만 대조한다.** 외부자료 및 공식 점수 역산 계수를 제거한 경로에서만 판단한다.

현재 원장·코드에는 최종 예측의 일부를 기존 답안 CSV에 의존하거나 공식 점수에서 계수를 구한 경로가 남아 있다. 따라서 **화면상 최고점, 데이터 출처가 깨끗한 기록, 최신 규정에 맞게 전 과정을 재생성하는 후보는 서로 다르다.** 이 구분을 먼저 고친다. 기존 연구를 삭제하거나 전면 재작성할 이유는 없다.

근거와 한계: [조사 결론](../reports/score_improvement_plan_20260905_v1/report-source.md), [출처 원장](../reports/score_improvement_plan_20260905_v1/claim-source-ledger.md).

## 3. 규칙과 불필요한 제약을 구분한다

### 강제 차단 조건

- 배포 외 관측·재분석·예보·원본 정답 접근, 해당 데이터에서 파생한 예측/계수/증강/선택 결과 사용.
- 공식 반환 점수를 역산하여 행별 정답, 분할 포함 여부, 계수·임계값·파라미터를 푸는 행위.
- 가림 target 누출, P3 미래/다른 사례 정보 혼입, train/validation 키 중복, 평가 label로 특징·전처리 적합.
- 예측 전체의 학습·추론 경로가 설명되지 않거나, 제출 형식·재생성·실행시간 조건을 만족하지 못함.

9월 2일 운영진 공지는 **정상적 모델 선택에 점수를 참고하는 것**과 **점수를 목적함수로 파라미터를 푸는 것**을 구별한다. 상수를 JSON으로 옮겨도 출처 문제는 해결되지 않는다. 일반적인 고정 seed·모델 구조·실험 hyperparameter 자체를 전부 금지하는 규정으로 확대하지 않는다.

### 위험 기록으로 낮출 조건

- 모든 월·정점에서 양수여야 한다는 조건, 최소 +3점/+0.3점, 변경행 비율 상한, P1 기존 양성 삭제 0은 일반 승격 필수조건으로 쓰지 않는다.
- 불확실성 구간이 0을 포함한다는 이유만으로 후보를 폐기하지 않는다. 효과 크기, 오차 집중, seed 변동을 공개하고 순위를 정한다.
- 반대로 +0.1점 상당을 넘었다고 자동 중단하거나, 과거 gate를 완화했다는 이유로 실패 후보를 즉시 승격하지 않는다.
- 재사용된 Q2/Q3/Q4 또는 재분할한 H1을 fresh holdout이라고 부르지 않는다. bootstrap도 이미 반복 노출한 검증셋을 새 독립 증거로 바꾸지 못한다.
- CPU-only, 모든 합성 사전학습 금지, 모든 숫자 상수 금지는 이번에 확인한 운영진 규정이 아니다. GPU는 가능한 실행 자원으로 남긴다. TabPFN은 허용 예외가 있지만 실적·비용 때문에 이번 최우선이 아니다.
- 이상치 제거는 자동 전처리가 아니다. P1 이상 label은 탐지 대상이고 P3 큰 파고는 중요 target이다. 삭제 후보가 필요하면 train 안에서만 규칙을 만들고 원본 control을 유지하며 평가 행은 제거하지 않는다. 이번 첫 비교에는 추가하지 않는다.

## 4. 실행 순서와 공통 산출물

세 문제를 병렬로 진행하되 문제별로 `기준 경로 확인 → 같은 테스트에서 비교 → 유망한 단일 변경 확인 → 전체 학습·제출물 재생성` 순서를 지킨다. 기준 확인이 끝난 문제는 다른 문제를 기다리지 않는다.

### A. 먼저 약 60~90분의 준비 예산을 둔다

이 시간은 **계획상 상한이며 실측 소요시간이 아니다.** 대용량 재학습으로 시작하지 않는다.

- 기존 untracked `docs/ocean_v2_codex/`, `reports/claude_recon_20260905/`와 최종 패키지, 실험 lock을 보존한다.
- 사용하려는 recipe의 `배포 입력 → 특징 → 학습 모델 → 내부 예측 → 후처리 → 최종 CSV` 의존 목록을 만든다. 금지 계보가 발견되면 그 부품만 대체한다.
- 기존 OOF는 키·split·모델·입력 출처·후처리 hash가 일치할 때만 재사용한다. aggregate RMSE/F1이 비슷하다고 같은 기준으로 취급하지 않는다.
- 기존 확정 실패를 다시 전수 재탐색하지 않는다. 아래 목록과 원장부터 확인한다.
- 평가 fold별 입력 목록, 가림 규칙, fitting 범위, metric 분모, 후보 수를 결과 보기 전에 기록한다.

### B. 모든 후보에 같은 결과 형식을 적용한다

- raw per-seed OOF 예측과 label/키 대응은 로컬 비공개 artifact로 저장. Git에는 행 단위 데이터가 아닌 집계·hash·recipe만 고려한다.
- P1: 합산 TP/FP/FN으로 pooled micro F1. 추가·제거의 TP/FP 효과, 장기사건별 recall, 정상구간 FP도 기록.
- P2/P3: `sqrt(전체 SSE / 전체 유효 target 수)`. fold RMSE의 단순 평균을 pooled RMSE로 쓰지 않는다.
- 정점·월·층·리드·결측 상태별 분해는 위험 진단이며 평가 행을 이중 가중하지 않는다.
- raw 모델 단독, 고정 reference, 최종 blend 각각 보고. clip 후 결과만 저장하지 않는다.
- config/코드/data-manifest hash, training fit 수, calibration fit 수, wall time, memory, official access, 오류/실패 유형을 함께 저장한다.

## 5. P1 실행 지시

### P1-A: 강한 기존 부품의 전체 재생성 경로

현재 패키지는 MS-TCN을 학습하지만 추론에서 `router_anchor.csv`와 GI 키별 패치를 추가 사용한다. 학습 코드가 없는 것은 아니다.

- O/XGBoost: `src/p1_qc/pipeline.py`의 `train_full_model`와 저장 함수.
- B/event-day LightGBM: `scripts/run_p1_meaningful_learning_curve_generation_v1.py`의 fullfit/save 경로.
- router: `scripts/run_p1_incumbent_preserving_mstcn_asrf_v2.py`의 조합 경로.
- GI2: `scripts/build_deadline_probe_set_20260828.py`의 일반 `novel & predicted spike` 규칙. 두 키를 답안에 직접 쓰지 말고 원래 모델 출력에서 재생성되는지 검사한다.

이 단계는 점수 개선 주장이 아니라 재현성 확보다. 기존 O/B 확률 OOF가 동일 split에서 검증되면 확률 재결합의 작은 진단을 먼저 할 수 있다. 이때 이미 본 outer truth에 임계값을 맞추지 않는다. 적합한 inner 자료가 없으면 아래 학습 예산에 포함한다.

### P1-B: 작은 트리 대조와 수정 자유도

주 가설: 낮은 확률로 놓치는 장기 offset/drift는 임계값만으로 복구하기 어렵고, 기존 양성을 무조건 유지하는 OR는 기존 FP를 고칠 수 없다.

1. 현재 event-day LightGBM recipe를 control로 고정한다.
2. 후보는 하나: 장기 문맥의 좌우 flank 차이, temp–psal/peer 불일치, 해당 요약의 관측 지원량. 이미 있는 특징과 중복이면 새 이름만 붙이지 않는다. 정확한 열·창 길이는 기존 라이브러리의 지원 범위를 확인한 뒤 결과를 보기 전에 manifest로 고정한다.
3. 각 모델에 대해 inner-only calibration으로 `standalone(0↔1 수정 가능)`과 `historical union`을 비교한다. OR 해제는 무조건 더 좋다는 결론이 아니라 검증할 자유도다.
4. Q2/Q3/Q4 전방 3fold, 같은 seed: `2 arms × 3fold × (inner fit + outer refit) = LGBM 최대 12 fits`.
5. O/XGB control의 올바른 inner/outer 예측이 없으면 별도 최대 6 fits를 명시한다. 이를 LGBM 12에 숨기지 않는다. 불필요한 MS-TCN 재학습은 screening에 포함하지 않는다.
6. intact와 label-independent fragmentation stress를 평가한다. gap은 정상 label에만 주입하지 않는다. offline QC의 양방향 관측 문맥과 미래 label 학습을 혼동하지 않는다.
7. purge는 특징+후처리의 실제 합성 의존 범위로 결정한다. 기존 21일 계약을 출발점으로 검산하되, 337h 창의 전체 폭을 자동 미래 누출 시간으로 해석하지 않는다.

최선 arm이 control보다 좋으면 그 arm과 control만 2개 추가 seed로 확인한다(동일 inner/outer 방식이면 LGBM 추가 최대 24 fits). 모두 나쁘면 seed 확장을 하지 않는다. 다음은 아래 조건부 분기다.

- 표현은 개선했으나 threshold 변동이 원인: 같은 모델의 inner calibration만 1회 교정.
- 확률에서도 장기 FN 개선이 없음: 현재 표현 수정은 종료. 오래된 oracle에서 특정 행/정점 규칙을 추출하지 않는다.
- 사건을 일부 탐지하지만 내부 누락이 남음이 **현재 control**에서도 확인될 때만 별도 사전등록 구간 decoder 1개를 다음 순번으로 둔다. 기존 단순 run extension/CAPA를 반복하지 않는다.

## 6. P2 실행 지시

### P2-A: 잘못된 기준을 이기는 실험부터 중단

v52의 내부 reference는 pooled 3.085715℃, Sep/Oct 4.882135℃인 반면 공식 기록은 0.424019℃다. 서로 다른 모집단·모델이므로 이 간극만으로 버그를 확정하지는 않지만, 실제 코드에서 prefix-only 내부 학습과 full-history 배포의 불일치가 확인됐다.

1. 61일 가상 가림의 목표층 temp/psal을 함께 가린다. 가림 구간 주변을 학습에 넣는 것이 허용되는 **복원 문제**로 평가와 배포 조건을 통일한다.
2. 양쪽 관측을 이용하되 가린 label 및 의존 범위를 침범하지 않게 purge한다. 기존 ±7일은 최소 출발점이며 실제 특징 범위가 더 크면 확대한다.
3. 배포본에 target QC 또는 동등한 마스크가 실제로 제공되는지 먼저 확인한다. 없다면 유한 target 및 공개 수온층 최소 2개 조건을 내부 proxy로 사용하고, 공식 hidden QC 선별을 정확히 재현한 것은 아니라고 명시한다. QC를 복원하려고 외부 원자료에 접근하지 않는다. 실제 수심 유효성, T5/S5 연속 결측 비율은 후속 실행에서 집계 재검증한다. Claude 문서의 비율은 이번 계획에서 새 실측으로 주장하지 않는다.
4. 무학습 기준: nominal interpolation와 T1 단순 기준. 학습 기준: bin17을 제거한 v23 단독, v52 단독, 배포 관측으로 다시 적합한 seasonal OAS.
5. 기존 5,889-parameter DeepSets 코드와 OAS 커널을 재사용한다. 평가 baseline과 추론 baseline의 외삽·결측 동작도 통일한다.

### P2-B: 순차 ablation

- screen 1: v23/v52 × 3fold × 1 seed = DeepSets 6 fits. raw 절대 예측을 반드시 저장한다.
- screen 2: 위에서 선택한 control에 T5/S5 **연속 결측 증강만** 추가, 3 fits. 관측 가림 뒤 baseline/scale/tokens를 모두 재계산한다.
- screen 3: 같은 control에 **목표 실제 depth + nominal + presence만** 추가, 3 fits. 목표 depth 사용 가능 여부를 먼저 검사한다.
- 둘을 동시에 넣거나 새 loss/트리/시간축/투영을 섞는 전면 개편은 첫 비교에 넣지 않는다.
- winner 하나와 control만 2개 추가 seed 대조: 추가 12 fits. 따라서 DeepSets screening+확인 최대 24 fits. OAS 학습, 내부 calibration, 최종 전체 학습은 별도 영수증으로 센다.

단독 모델들의 오차가 실제로 상보적이면 OAS/DeepSets 결합을 다음 순번으로 둔다. 첫 비교는 사전고정 50:50 평균 한 개로 충분하다. 연속 가중치를 학습하려면 각 outer fold의 train 내부에서만 적합한다. 중첩된 내부 OOF가 없으면 임의의 cross-fold 재활용으로 독립성을 주장하지 않는다. 공개 점수로 최적 blend/단독 성능을 역산하지 않는다.

bin17 CSV를 포함한 과거 최종 답안과 0.424019℃는 역사 기록으로 보존한다. 새 경로의 성적은 별도로 측정하고 기존 최고를 복제했다고 선언하지 않는다.

## 7. P3 실행 지시

### P3-A: 0-fit 비교표부터

`artifacts/p3_corrected_repeated_forward_catboost_v2/` 등 clean recipe의 OOF를 출처까지 대조한다. 외부 correction 또는 공식 점수 적합 계수가 섞인 부품은 제외한다.

- 같은 키·정답·리드에서 single/multi/router/persistence shrink/TabPFN standalone 및 기존 25% blend를 비교한다. raw standalone OOF가 없으면 역복원하지 말고 누락으로 기록한다.
- 기존 181사례/1,086행 전방 평가면을 기본으로 유지한다. 78h·hs≥1.5·6개 유효 리드·독립 episode는 이미 구현됐다. 이를 새로운 개선처럼 재구현하지 않는다.
- first-eligible greedy가 운영진의 실제 추출 알고리즘이라고 단정하지 않는다. dense/onset 추가 평가면은 민감도 분석이며 새 독립 자료라고 부르지 않는다.
- 최종 metric은 모든 리드의 SSE를 합친 RMSE. 6h 하나의 양수를 전체 개선으로 표시하지 않는다.

### P3-B: 기상 결측 증강 대조 1개

기존 compact residual tree recipe의 clean 경로를 control로 한다. 기상 미관측 구조를 학습한 모델이 기상 관측 환경으로 전이할 때 약해지는지 시험한다.

- 동일 3 전방 folds × control/증강 2 arms × 2 seeds = 최대 12 tree fits.
- 증강은 train의 기상 관측 사례에서 기상 파생 특징을 **묶음으로** 가린다. 원본/가림 표현의 총 가중치를 각각 0.5로 고정하여 사례별 학습 총중량이 달라지지 않게 한다. 결측 indicator 및 전처리도 함께 일관되게 재계산한다.
- hs와 target은 변형하지 않는다. 같은 사건의 6개 리드에 모순된 결측 패턴을 만들지 않는다.
- 증강 비율 HPO는 하지 않는다. control/standalone 및 사전고정 25% fallback blend를 모두 집계한다.
- CPU 한 worker, 초기 6threads. P2와 메모리/CPU 경합 시 자원만 줄이고 모델 조건을 바꾸지 않는다. 45분은 계획상 screening 예산이지 완료 시간 예측이 아니다. 초과 시 조용히 epoch/iterations를 바꾸지 말고 해당 예산의 미완료로 보고한다.

후속 0-backbone-fit 후보는 최대 3개 이내다. 이미 본 결과에서 6h-only TabPFN25 혼합이 가능성 있는 예이지만, 이는 **사후 탐색 후보**이며 fresh confirmation이 아니다. 전체 TabPFN25는 이미 악화했으므로 똑같은 실험을 반복하지 않는다. 같은 검증면에서 상보성이 없으면 더 많은 blend 조합 대신 이 가지를 종료한다.

## 9. 시간·자원·제출 판단

- 분석 주의력 우선순위: P1 약 50%, P2 30%, P3 20%. 이는 성능 보장이 아닌 초기 배분이다. 관측된 실험 시간과 내부 개선이 나오면 재배분한다.
- 첫 0-fit 비교가 끝난 즉시 가장 싼 유망 arm부터 진행한다. GPU를 쓰는 큰 재학습 2개는 동시에 시작하지 않는다. 모든 CPU worker 수를 개별 문제가 아니라 합계로 관리한다.
- 코드 변경 전 현재 실행 중인 프로세스와 artifact 충돌 여부를 확인한다. 기존 one-shot을 재시작하거나 덮어쓰지 않는다. 새 변경은 별도 experiment ID로 기록한다.
- 운영진 8월 12일 제출 안내에서 모델 코드/가중치 기한 **9월 7일**을 확인했다. 홈페이지 소개 일정과 혼동하지 않는다. 정확한 종료 시각과 6시간 검증 환경의 범위는 최종 실행 시작 시 다시 확인해야 한다. 확인 전에는 보수적으로 모델 제출 준비를 먼저 확보한다.
- 일일 3회 한도는 제출 직전 홈페이지에서 남은 횟수를 읽는다. 계획 작성 시점의 이력을 현재 남은 횟수로 가정하지 않는다.
- 1순위는 동일 내부 평가에서 가장 좋은 재현 가능한 후보. 2순위는 정말 다른 오류를 줄이는 차순위/불확실 후보. 3번째 기회는 남은 시간과 추가 정보의 가치에 따라 쓰며 같은 SHA는 다시 내지 않는다.
- 공식 점수는 후보 전체 비교에 참고한다. 공식 결과를 보고 행·정점·리드 계수를 역산하거나 누가 Public인지 추론해 다음 답안을 만들지 않는다.
- 구조/출처/누출/재현 조건이 통과하면 일부 정점 악화나 CI가 0을 포함해도 점수 우선 후보로 기록할 수 있다. 손상 크기와 근거 부족을 숨기지 않는다.
- 후보가 control보다 나쁘면 control을 유지하고 정해진 다음 ablation으로 이동한다. 기술 실패는 성능 실패와 구분한다. 실패를 이유로 무제한 새 방법 생성/HPO를 시작하지 않는다.
- 최종 제출 전에는 기존 제출 CSV를 필수 입력으로 삼지 않고, 모든 앙상블 부품을 배포 자료에서 학습·추론해 재생성한다. 새 실행 안에서 만들어지는 중간 예측/앙상블 자체를 금지하는 것은 아니다. 배포 자료→학습→모델 저장→별도 프로세스의 예측을 완주한다. 저장 모델의 반복 inference 일치와 재학습 후 차이 분포는 별도 검사한다. SHA 차이만으로 재학습 실패나 규정 위반을 단정하지 않는다.
- 필요한 재현 실행과 패키징 시간을 확보한 이후에만 추가 탐색에 자원을 쓴다. 마감 직전 검증되지 않은 파이프라인으로 전부 갈아끼우지 않는다.

## 10. 낮은 추론 강도의 실행자에게 전달할 지시

> `docs/SCORE_IMPROVEMENT_PLAN_20260905.md`와 연결된 조사 원장을 먼저 읽고 실행한다. 코드 전체를 새로 만들지 말고 기존 O/B, DeepSets/OAS, clean tree 경로를 재사용한다. P1/P2/P3 각각 담당자를 두되 같은 파일/모델/GPU를 중복 점유하지 않는다. 첫 산출물은 문제별 적격 reference와 동일 내부 평가 계약이다. 과거 최고점 CSV에 기대어 새로운 최고 모델이라고 쓰지 않는다. 각 문제의 위 fit 예산과 순서를 지켜 실제 학습·내부 테스트·후보 완성까지 진행한다. 성능이 나쁘면 control을 보존하고 위에 정한 다음 축으로 이동한다. 질문 대신 독립적으로 처리 가능한 세부사항은 결정하고 기록하되, 규정 해석·새 권한·마감/자원상 불가능은 숨기지 말고 보고한다. 사용자에게는 내부 F1/RMSE, 조건부 점수 환산, 공식 점수, 소요시간, 다음 행동을 구분해 보고한다. 계획에서 정하지 않은 대규모 HPO·모델 전환·외부자료·Public 역산·Git 이력 변경은 하지 않는다. 업로드/commit/push는 해당 실행 시점의 사용자 승인 범위를 따른다.

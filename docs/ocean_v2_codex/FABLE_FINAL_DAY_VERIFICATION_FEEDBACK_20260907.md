# Fable 마감일 계획 검증 피드백 — 2026-09-07

## 결론

**P1 제안은 서로 다른 범위 규칙을 혼동했고, P2 투영의 정확한 수치는 재현되지 않았다. P3 shrink 제거의 평균 개선은 재현됐으며, OLS 계수의 적용 대상은 명확히 수정해야 한다.**

검증 대상: [FINAL_DAY_PLAN_20260907.md](FINAL_DAY_PLAN_20260907.md) §1-1·§2·§3·§5 및 [PREPROCESSING_RECON_20260906.md](PREPROCESSING_RECON_20260906.md). 두 문서는 원문 보존한다. 최신 사용자 요청은 불일치하면 해당 후보를 만들지 않는 것이므로 **P1/P2 새 후보는 생성하지 않았다.** 공개 점수를 사용해 수치·규칙을 조정하지 않았다.

독립 검증은 기존 OOF와 배포자료의 집계만 사용했다. 새 모델 학습 0, 새 답안 CSV 0, 업로드 0, hidden truth 접근 0. 과거에 노출된 OOF이므로 새로운 독립 holdout이나 공식 성적 예측으로 해석하지 않는다.

## 1. P1: 고정 0~35℃와 학습 정상 min/max는 다른 규칙

배포 train 776,706행, test 169,011행 및 채점 답안 SHA `57844ef235f987059d17bddb035cc0a98b92bb0d53263cf878c68b31bbc53687`를 키·순서 대조 후 계산했다.

| 규칙 | 하한 / 상한 ℃ | train label 0 이탈 | train label 1 이탈 | test 이탈 | 그중 기존 label 1 | 새로 양성 처리될 행 |
|---|---|---:|---:|---:|---:|---:|
| **실제 train label 0 min/max** | **5.0017 / 30.8965** | 0 | **2,716** | **653** | **534** | **119** |
| Fable의 **고정** 물리 범위 | **0 / 35** | 0 | **805** | **123** | **103** | **20** |

정정 사항:

1. 805/123/103/20행은 고정 0~35℃의 결과다. 이를 train min/max에서 직접 도출한 수치라고 쓰면 틀리다.
2. 정상 train의 min/max로 정의한 구간 밖에 정상 train이 0행인 것은 **정의상 당연**하다. 독립 검증의 FP 0 증거가 아니다.
3. test 정답을 모르므로 20행 또는 119행은 **추가 양성 예측**이지 확인된 TP가 아니다. “FP 0 확실”, “공짜 규칙”, “정답 20행 추가 포착”을 삭제한다.
4. 0~35℃를 택하려면 이를 허용하는 배포 README/문제지의 명시적 근거나 별도의 train-only 학습·내부평가 절차가 필요하다. 현재 요청의 “min/max 직접 산출, 리터럴 금지”를 만족한 것처럼 포장하지 않는다.
5. 규칙을 평가하려면 fold별 학습 정상에서 범위를 적합하고 검증 블록 FP/FN/pooled F1을 측정해야 한다. 공식 입력에서 변하는 행 수만으로 성능 향상을 확정하지 않는다.

**판정: 요청한 fitted-range 수치와 불일치. `P1_champion_rangerule` 생성 보류.**

## 3. P3: shrink 제거 근거 재현, OLS 정의 정정

원 OOF: `artifacts/p3_numeric_lead_forward_gpu_20260906_v2/candidate_oof.parquet`, 103,602행/17,267 anchors/951 station×episode clusters. SHA `b7a28e2d52ba0c8d65d39e08775bf7a0248b2dd128c23c7f9afe0f489551ded2`는 원 result와 일치한다.

12/18/24h에서만 `(final−0.2·persistence)/0.8`로 복원하고, 나머지 리드는 불변이다.

|---|---:|---:|---:|
| 0 | **0.679831** | 0.777755 | **0.629366** |

| 0.3 | 0.690228 | 0.795858 | 0.615218 |

station×episode 단위 paired bootstrap 10,000회, seed 20260907:

- w=0 − w=0.2 pooled ΔRMSE = **−0.003707m**.
- **P(개선)=0.9076**, CI90 **[−0.008301, +0.000982]m**.
- Fable의 ≈0.91 및 CI90 [−0.0078,+0.0009]와 대체로 정합. bootstrap seed·횟수·cluster 순서가 명시되지 않아 CI의 byte-exact 일치까지 요구하지 않았다. CI는 0을 포함한다.
- hs0<1.7에서는 **악화**가 재현됐다. 이는 onset의 근사 부분집합이지 onset 정답 라벨 자체가 아니다.
- §2의 “내부 OOF는 shrink 소폭 선호”는 §1-1 및 해당 numeric OOF pooled 결과와 모순이다. **pooled는 제거 선호, 저파고 부분집합은 유지 선호**라고 쓴다.
- w=0.1 통계는 요청된 재계산 표에만 기록한다. 이를 보고 새로운 후보 슬롯이나 계수를 자동 선택하지 않는다.

### OLS 계수는 예측값 자체에 곱하는 값이 아니다

Fable 수치와 가까운 계수는 다음 모델의 OLS이다:

`corrected = persistence + a_L × (no_shrink_prediction − persistence)`

`a_L = sum((prediction−persistence) × (truth−persistence)) / sum((prediction−persistence)^2)`

| lead h | 위 변화량 OLS a_L | 예측 자체에 곱하는 through-origin OLS |
|---|---:|---:|
| 3 | **0.705577** | 1.011877 |
| 6 | **0.850803** | 1.003536 |
| 9 | **0.847352** | 1.002041 |
| 12 | **0.920378** | 0.977214 |
| 18 | **0.954592** | 0.945472 |
| 24 | **0.973336** | 0.915384 |

따라서 “예측에 리드별 승법 보정”이라고만 쓰면 구현을 잘못할 수 있다. 또한 계수를 적합한 OOF에 다시 평가한 이득은 **in-sample**이다. JSON 저장 자체가 적격성이나 일반화 성능을 보장하지 않는다. 현재 슬롯 1/2에는 OLS 보정을 넣지 않는다.

**판정: shrink 제거 pooled 및 부분집합 반전의 핵심 수치 재현. P3 CPU 결정론 준비의 근거는 유지된다.**

## 4. 계획서의 나머지 수정 사항

- P3 과거 cold 차이의 원인을 “GPU multi 비결정”으로 단정하지 않는다. 현재 입증된 사실은 660행 답안 차이이며 원인 분리 실험은 없었다. CPU 전환은 위험 제거 가설이고, 두 번의 cold SHA 대조가 필요하다.
- “CPU니까 결정론”도 결과 확인 전에 완료 판정하지 않는다. 새 CPU 3-seed 전체 chain은 5 historical folds×3seed×2 backbone + full 3seed×2 + 4 prior routers + full router = **36+5=41 fits/cold, 두 번 82 fits**로 사전등록했다. 이는 full fit만 세는 비용 표와 구분한다.
- §3·§6은 옛 P2 순서(seed10→projection)가 남아 있다. 최신 §1-1·사용자 지시의 **projection 검증→3seed projection→round1 결과 후 10seed projection**으로 통일한다. “P2 슬롯1(seed10)”은 현재 지시가 아니다.
- 과거 Public 적합 α 또는 외부자료 계보의 결과를 새 후보의 유효 성능 근거로 재사용하지 않는다. 현재 P3 shrink 제거는 위 배포자료 OOF 근거만으로 설명할 수 있다.
- P1 전체 재학습 비용 6,323초를 인정하면서 신규 후보 모두의 cold 증거를 요구하고 “MS 재학습하지 않음”을 동시에 지시한다. 후처리 전용 후보는 **정확히 같은 기반 cold 증거 + 새 후처리의 독립 재생**을 허용하는지, 새 전체 cold를 요구하는지 명시해야 한다. 저장 추론을 새 전체 학습으로 부르지 않는다.
- 사용자 답변 기준 문제당 남은 기회 3회는 확인했으나 **공식 마감 시각은 아직 모름**이다. 15:00은 내부 후보 확정 목표이지 확인된 공식 마감이 아니다. 브라우저는 `Debugger unattached`, 공개 홈페이지 읽기도 마감 텍스트를 반환하지 않았다. 로그인 화면에서 사용자가 확인해야 한다.
- “SOURCE_ONLY/SAVED_MODELS 모두 50MB 이하”와 P1 590MB 원 ZIP을 구분한다. 업로드용 분할 파일 각각의 bytes·개수와 재조립 SHA, 최신 포털 제한을 확인해야 한다.
- 최종 삭제 목록은 **미실행 체크리스트**다. 날짜·점수만으로 자동 삭제하지 않고 레코드 ID/계보/접수 증거를 사용자 화면에서 대조한다. 본 작업에서는 업로드·삭제·최종 잠금 모두 하지 않는다.

## 5. 검증 도구 자체의 주석과 재사용 범위

- 집계 JSON의 P2 `fallback_endpoint_rows: 0`은 초기화 후 집계되지 않은 보조 카운터다. **실측값으로 사용하지 않는다.** 예측 계산에는 실제 T5→T6→T7→T8 fallback이 적용되어 있으며 해당 카운터는 수치에 영향을 주지 않았다. 원 영수증은 보존하고 이 주석으로 정정한다.
- w=0.2를 대수적으로 복원했다가 다시 적용하면 float 반올림이 발생한다. 기준 대 기준 bootstrap의 작은 비영(非零) `p_improve`는 **성능 차이가 아니라 반올림 효과**이므로 해석하지 않는다. 중요한 w=0 비교의 0.9076과 CI는 별도로 보고했다.
- 재계산 코드의 단위 테스트 4 PASS/Ruff PASS. P3 CPU 어댑터 구조·seed/fit-count·CPU override 테스트 3 PASS/Ruff PASS, 별도 합성 CPU 반복 fit 4회 PASS. **실제 CPU cold 학습은 이 정정 문서 작성 시점에 아직 시작하지 않았다.**
- SOURCE_ONLY CPU 후보 코드는 준비됐지만 완성 제출물은 아니다. P1/P2 후보 CSV 및 `UPLOAD_SET_2`의 READY 파일은 아직 없다.

## Fable에게 요청할 수정

P1/P2는 기대값을 바꾸거나 구현을 수치에 맞추기 전에 **원 계산 코드와 정확한 규칙을 먼저 제공**한다. 위 표와 대조해 계획서를 정정하고, 확정 사실·가설·미검증 적격성을 분리한다. 새 구조/탐색을 추가하지 않고 어떤 후보가 현재 사용자 지시의 검증 조건을 통과했는지를 명확히 표기한다.

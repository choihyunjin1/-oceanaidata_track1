# 앞으로의 길 — Codex 검토 반영 (2026-09-05 저녁 기준, 마감 09-07 모델 제출)

## 0. Codex 판단에 동의하는 것 (앞으로의 작업 원칙)
1. 평가 지표·분할·선택 절차를 먼저 고정하고, 그 뒤 변경은 **하나씩 분리**해 기준 대비 기여를 측정한다. 분류기와 후처리를 동시에 바꾸지 않는다.
2. 사양서의 "기대 Public 범위"와 리더보드 역산에서 나온 계수·예상 성적은 **근거에서 제외**한다. 업로드 점수는 파이프라인 버그 검출용 sanity로만 쓴다.
3. 안정성(worst-block) 악화는 자동 탈락 사유가 아니라 **별도 열로 보고**하고, 최종 선택 시 평균 이득과 하방 위험을 같이 본다. 하방 위험이 큰 변경은 fallback 후보와 함께 준비한다.
4. P2의 "T5 결측 전문가" 반복은 우선순위 낮음(첫 seed 이득이 3-seed에서 재현되지 않음). 실제 수심·프로파일 구조 가설은 별개로 유지.
5. 문서는 재설계 재료다. 자신감 수치는 믿지 않는다.

- (a) `03_model/`을 비우고 `RUN_TRAINING → RUN_INFERENCE`를 돌리면 `05_answer/*.csv`가 코드만으로 다시 만들어진다.
- (b) 예측 경로에 과거 답안 CSV, 다른 실행의 예측 파일, 리더보드 점수로 정한 상수가 없다.
- (c) 예측 경로의 숫자 리터럴이 README에 적힌 물리·구조 상수뿐이고, 적합된 값은 학습이 만든 JSON에서만 온다.

현재 `artifacts/official_final_submission_20260905/` 기준으로 통과하지 못하는 요소:
| 문제 | 통과 못 하는 요소 | 처리 |
|---|---|---|
| P1 | `03_model/decision_artifacts/router_anchor.csv`(양성 6,061행, 08-26 제출물 복사) + `gi_spike2_patch.json`(공개 점수로 고른 2행) | 제거. 트리 모델(O: XGBoost offline 80특징)을 패키지 안에서 재학습하고, 정점·층 라우팅은 OOF에서 코드가 선택하거나 아예 제거 |
| P2 | `03_model/decision_artifacts/bin17_anchor.csv`(예측의 80%, LB 적합 계보) | 제거. DeepSets 3-seed(재생성 가능)를 기준으로 삼고, OAS 계절 프로파일은 데이터에서 계산하되 혼합비는 CV로 |

따라서 **기준 모델 B = 위 요소를 뺀 뒤 남는 재생성 가능한 코어**이며, 이것을 먼저 만들어 클린룸 검사 (a)~(c)를 통과시킨다. 그 전까지 어떤 개선 실험도 "기준 대비"가 성립하지 않는다.

문제별 최소 준수 기준 모델:
- **P1-B**: `p1_qc` CLI로 XGBoost O 재학습(fold 내부 OOF로 hysteresis/min-run 선택) ∪ MS-TCN e150 3-seed(패키지 `train_model.py` 재학습). MS-TCN은 fp32 + `torch.use_deterministic_algorithms(True)` + cudnn deterministic으로 재학습해 두 번 실행 시 행 불일치 0을 목표로 하고, 안 되면 README에 재학습 허용오차(불일치 행 수)를 기록. GI 2행 제거. 라우팅은 코드화(OOF 셀별 선택) 또는 제거 중 CV로 결정.
- **P2-B**: DeepSets v52 3-seed 단독(실제 수심 여부는 별도 실험) + envelope/PAVA 투영. bin17 미사용.
- **P3-B**: single+multi CatBoost(CPU 결정론) 등가 평균 + clip[0,30]. shrink·α·axis 없음. 라우터는 OOF에서 재적합되는 경우에만 허용.

## 2. 먼저 고정할 평가 절차 (문제별 한 페이지, 코드로 고정, 이후 변경 금지)
| 문제 | 분할 | 1차 지표 | 함께 보고 |
|---|---|---|---|
| P1 | 반기 4블록(H1_2024, H2_2024, H1_2025, H2_2025), 양측 purge 21일, 양성 run 시작 블록 귀속 | f1_season(H1 두 블록 풀링) | f1_pooled, worst-block, 유형별 recall, 계열별 예측률, 단절 스트레스 F1, 일-블록 부트스트랩 CI90 |
| P2 | 2개월 블록 8개, purge 7일, 각 블록 testmatched(마지막 17일 T5 제거) 변형 | Composite = sqrt(0.71·pooled² + 0.29·outage²) | 블록·층·T5 유무별 RMSE, 비교군(nominal 보간·실제수심 보간·T1 복사·DeepSets 단독) |
| P3 | 6분기 블록, purge 78h + episode 제외 | S_dense(onset 정합 가중) | S_greedy(272), 리드·정점·블록별, persistence 비교, episode 부트스트랩 CI90 |
선택 절차(사전 고정): 변경마다 기준 대비 평균 Δ, CI90, P(개선), worst-block Δ, 정점/층/리드별 Δ를 한 표에 보고. **승격 = 평균 Δ 개선 ∧ P(개선) ≥ 0.8**. 악화 위험은 별도 열(자동 탈락 아님). 최종 후보는 승격 누적본이되, worst-block 악화가 큰 변경이 포함되면 그 변경을 뺀 버전을 fallback으로 함께 패키지 후보에 둔다.

## 3. 분리 실험 순서 (각 실험 = 변경 하나, 기준 B 대비)
- **P3** (각 ≤30분): ① shrink·α 제거 자체의 효과(=B 확정) → ② onset 위상 특징 추가 → ③ 바람-드롭아웃 증강 → ④ 오차 구조가 다른 멤버 추가(LightGBM per-lead) 등가 평균 → ⑤ seed 3→5. 표본가중·a_L 보정은 후순위(로컬 근거가 Public과 반대였음을 기록만).
- **P1** (후처리 고정 상태에서 분류기 변경만 먼저): ① 기준 B 재현 → ② 시간 기반 간격 허용 창 특징 → ③ psal 쌍둥이 특징 → ④ 브래킷(점프쌍) 특징 → 그 다음 분류기를 고정하고 후처리/구간 완성만 ⑤ 하드 flatline+edge0 → ⑥ 유형별 구간 완성 → ⑦ Stage-2 스태킹. 각 단계의 유형별 recall 변화를 필수 기록.
- **P2**: ① DeepSets 단독 기준 → ② 실제 수심 목표(zt_real) → ③ 시간 문맥 토큰(±1/6/24h 차분) → ④ 3목표 LightGBM 병행 멤버(균등 평균) → ⑤ 데이터 산출 OAS 혼합(α는 CV). T5 전문가 반복은 하지 않음.

# Fable 추가 검토 — 적용 사항과 정정

## 판단

**재생성 답안과 공식 점수의 연결, 평가 모집단의 정합성, 최종 패키지를 우선하자는 방향은 채택한다.** 단, 이미 실행 중인 봉인 실험의 분할·선택 기준을 결과 도중 바꾸지 않는다. 현재 실행을 마치고 별도 계약으로 다음 비교를 구성한다. 새 학습을 추가로 자동 시작하지 않는다.

검토 방식은 `validate-data` 및 `analyze-data-quality`: SHA 기반 동일성, 공식 receipt, 평가 행의 모집단/지원, 실제 실행 시간을 분리했다. 원본의 행별 값·공식 숨은 정답은 노출하지 않는다.

## 확인된 사실 / 정정

| 주장 | 대조 결과 | 조치 |
|---|---|---|
| P2 clean 답안이 채점됐는지 불명 | 동일 SHA가 09-05 채점됨. RMSE 0.455143℃ | 기존 점수 있는 fallback 유지, 중복 제출 불필요 |
| P3의 현재 재생성 코어 점수는 08-25 O 0.607071 | 현재 SHA의 공식 기록은 09-05 **0.607183m** | 두 파일/모델을 혼동하지 않음 |
| P1 새 답안은 기존 0.8335와 불일치 | 새 SHA는 미채점. 실제 재생성 비교 대상인 다른 clean SHA의 점수는 **0.790733**. 0.833548은 또 다른 과거 계보 | 새 답안에 둘 중 어떤 점수도 승계하지 않음 |

공식 점수·파일·validator·절대경로는 [UPLOAD_SET_1.md](UPLOAD_SET_1.md)에 기록했다. 점수는 저장된 브라우저 receipt의 값이며 오늘 포털 현재 상태/쿼터를 다시 조회했다는 뜻은 아니다.

## 평가 수정의 적용 방법

1. **현 v5:** [CONTRACT.md](CONTRACT.md) 유지. P1 bracket, P2 crossfit, P3 numeric의 기존 runner/config/lock은 변경하지 않는다. 결과 기반 리스타트·기준 변경 없음.
2. **P1 차기 계약 후보:** 같은 3개 검증 반기를 두고 배포 학습 자료의 나머지 시간대를 양측 train으로 사용, 양측21일 purge와 전체 양성 run 격리를 적용한다. 정점·층이 실제로 전부 지원되는지 source-only 검사한다. 미지원 행을 주 지표에서 임의 삭제하는 방법보다 이 방향을 우선한다. 과거와 미래 자료를 함께 쓰는 retrospective 평가임을 명시하고, 전체 H1_2025를 같은 평가키로 B/변경안 비교한다. v5보다 숫자가 높아지는 것 자체는 모델 개선이 아니다.
3. **P2:** B4/B8 빈 outage는 이미 명시 제외돼 있다. 다른 블록의 outage를 평균에 넣을 때 동일 target keys와 분모를 사용한다. 실제 깊이·시간 문맥 제안은 이미 실행된69feature physical-tree와 기존C3 11feature를 먼저 대조한다. 모델 구조/시간 토큰 표현 차이를 확인한 뒤 별도 변경으로 다루며 과거 결과를 새 구조의 실패 증거로 과대 일반화하지 않는다.
4. 새 계약/입력 adapter 테스트/지원 확인 후 **같은 새 계약의 B를 먼저 학습**한다. 이미 노출된 역사 자료를 fresh holdout이라고 부르지 않는다. 현재 v5 개선을 새 양측 계약 개선으로 옮겨 적지 않는다.

## 패키지 이관 전 확인

`PACKAGING_SPEC.md`의 `src/ocean_v2`, `scripts/ocean_v2`, `configs/ocean_v2`, `tests/ocean_v2` 경로는 이 확인 시점에 아직 없다. 따라서 사양의 `python -m ocean_v2.p?` 명령이 이미 실행 가능한 것으로 안내하지 않는다. 기존 재생성 driver/의존 함수에서 문제별 portable 코드를 만들고, 원 저장소 import/개인 경로가 없는지 검사해야 한다.

수정 로드맵에 따라 PACKAGING_SPEC의 오래된 문구도 다음과 같이 해석한다.

- 숫자 리터럴을 물리 상수로만 제한하거나 JSON 저장을 강제하지 않는다. 사전 고정 설정/문제 정의/학습 산출물의 **출처 감사**가 기준이다.
- 기대 Public 점수 범위를 역산해 README에 넣지 않는다.
- 기존 `03_model`을 지우지 않고 **새 독립 임시 디렉터리**를 빈 상태로 만든다.
- 데이터는 로컬 참조·선택적 복사로 다루고 업로드 ZIP에서는 제외한다. 하드링크 사용 시 원본 수정 위험을 통제한다.
- 새 CPU 내부 실험의 모델을 기존 GPU clean 답안의 weights로 교체하지 않는다. 모델/환경이 바뀌면 생성 답안 SHA를 새로 확인한다.
- 저장 모델 replay, 두 차례 전체 scratch 재학습, 원 저장소 접근 없는 portable cleanroom, 실제 운영진 검증은 별도 판정이다.
- 파일 크기·최종 잠금 효과는 실제 포털 요구와 대조해야 한다. 로컬 패키지 생성이 공식 제출 완료는 아니다.

현재 새 portable cleanroom 학습/패키지 검증은 **미실행**이다. 이 문서는 미실행을 PASS로 표시하지 않으며 commit·push·upload도 수행하지 않았다.

### C-1. P3 no-shrink — 왜 내부 개선이 test에서 뒤집힐 가능성이 큰가

**확정 사실(재계산, 원시 행 미출력)**

입력: `completion_1/04_logs/candidate_oof.parquet`(SHA `bede4edf…`, 103,602행, 열 `fold, anchor_id, station, anchor_time, episode_id, current_hs, lead_h, target_hs, single_prediction, multi_prediction, persistence, final_prediction`)와 배포 `test_context.parquet`의 `step_minute==0` hs(200 사례). shrink 역변환 `routed = (final − 0.2·persistence)/0.8`(12/18/24h)로 만든 후보의 SSE는 Codex 값 47,546.9931632454와 일치(기준 48,091.9523451907).

| [1.5, 1.6) | **0.400** | 0.119 | 0.6098 | 0.6201 | +0.0103 |
| [1.6, 1.7) | 0.200 | 0.104 | 0.6253 | 0.6348 | +0.0096 |

| [2.4, ∞) | 0.100 | **0.342** | 0.7452 | 0.7232 | **−0.0220** |

- test hs0 분위 p10/25/50/75/90 = 1.52 / 1.55 / 1.64 / 1.865 / 2.392, hs0<1.7 비율 0.60. OOF는 hs0≥2.4가 행의 34%.
- 내부 pooled 개선(−0.0039)은 전부 hs0≥2.4 구간에서 나오고, 나머지 네 구간은 모두 악화한다.
- OOF 행을 test 구간 비율로 재가중한 RMSE: 기준 0.641526 → 후보 **0.646559 (+0.005033)**. station×episode 951블록 paired bootstrap 2,000회: CI90 [+0.002354, +0.007736], P(개선)=0.001. 리드별 재가중: 12h 0.6464→0.6534, 18h 0.7639→0.7736, 24h 0.8097→0.8188.
- 같은 방법을 GPU OOF(ff42a6a0 계보, `artifacts/p3_numeric_lead_forward_gpu_20260906_v2/candidate_oof.parquet`)에 적용해도 방향이 같다(w=0 재가중 0.6435 vs w=0.2 0.6434에서 시작해 저파고 악화).
- Public 확정 사실: 기반 2015b387 0.609836 m vs ff42a6a0 0.604351 m. no-shrink는 최고 Public을 넘을 수 없으므로 리더보드 집계("문제별 Public 최고 점수")를 바꾸지 못한다.

**가능한 설명**: 사례 선정 규칙(README: "기준시각 hs≥1.5m")과 정찰(onset greedy 재현)대로 test 기준시각은 폭풍 초입의 낮은 파고에 몰려 있다. 낮은 hs0에서는 모델의 변화량 예측이 과대해 지속성 혼합이 이를 눌러 주고, 높은 hs0에서는 반대다. shrink 제거는 높은 파고에서만 이득이다.

**미검증 가설**: hs0 재가중이 공식 점수 방향을 정확히 예측한다는 것. test 사례는 hs0뿐 아니라 onset(최초 교차·상승) 조건도 갖는데 OOF에 onset 플래그 열이 없어 이 축은 맞추지 못했다. onset 사례는 hs0가 더 낮으므로 방향이 바뀔 이유는 없으나 크기는 다를 수 있다.

**계수 재조정 격자(참고, 후보 아님)**: w_short∈{0,0.1,0.2,0.3}×w_long∈{0.2,…,0.6}을 재가중 표면에서 보면 현재 (0, 0.2)가 2025 fold에서 최선 근처이고, 2024 fold에서 고른 (0.3, 0.4)는 2025에서 +0.011 악화한다. 최선 대안 (0.1, 0.3)의 재가중 Δ는 −0.0016~−0.0018, CI90이 0을 포함. 노출 OOF에서 고른 사후 계수이므로 슬롯을 쓸 근거가 못 된다.

## F. no-shrink 제출을 지연시킬 필요가 있는가

- **지연이 아니라 보류**다. 기술 QA(별도 PID replay, ZIP 추출 replay, 단기 리드 불변, 역변환 exact)는 완료됐고 추가로 확인할 파일·검사는 없다. 보류 근거는 §C-1의 test-hs0 재가중 결과 하나이며, 이 계산의 독립 재현(§E 1번)이 유일한 추가 검사다.
- 제출해도 리더보드 최고 Public(ff42a6a0)을 바꿀 수 없으므로 점수상 이득이 없고, 정보 가치만 있다.
- **제출이 합리적인 유일한 분기**: 사용자가 재현 우선으로 P3 최종을 CPU 계보로 정하고(ff42a6a0 등 상위 Public 항목 삭제 포함), CPU 두 변형(2015b387 vs 70761aff) 중 하나를 Public 참고로 고르려는 경우. 이때도 §C-1은 2015b387 쪽을 가리킨다.
- 원격 업로드·최종 지정은 이 검토의 권한이 아니다.

## 정정 (2026-09-07 13:05 KST, Codex 반론 반영)

1. §A·§C-1·§F의 "no-shrink는 최고 Public을 넘을 수 없다"는 표현을 철회한다. 확정 사실은 두 가지뿐이다: (i) 리더보드 집계는 문제별 Public 최고 점수이므로 no-shrink가 집계를 바꾸려면 Public RMSE가 0.604351 m보다 좋아야 한다, (ii) test-hs0 재가중 OOF는 그 반대 방향(+0.005033 m)을 가리킨다. 따라서 정확한 문장은 **"넘을 가능성을 뒷받침하는 근거가 약하다"** 이며, 재가중 OOF는 예측 근거이지 공식 결과가 아니다. 이 재가중 수치는 Codex의 독립 재계산 전이다.
2. §F의 "제출이 합리적인 유일한 분기"를 철회한다. 제출이 합리적일 수 있는 경우: (a) Codex 재계산이 재가중 악화를 재현하지 못하는 경우, (b) 사용자가 P3 최종을 CPU 계보로 정해 CPU 두 변형 중 하나를 Public 참고로 고르는 경우, (c) 마감까지 시간이 있고 다른 후보가 없으며 정보 가치를 위해 사용자가 슬롯을 쓰기로 하는 경우. 일부 구간 악화만으로 자동 탈락시키지 않는다는 원칙은 유지한다. 본 검토의 권고는 "우선순위 낮음·보류"이며 영구 보류가 아니다.
3. §A·§D의 삭제 항목은 "먼저 대조, 그다음 사용자 판단"으로 읽는다. 순서: 최종 검증 대상이 어느 답안인지(최고 Public인지, 최근인지, 선택형인지) 확인 → 채점 완료 답안의 삭제 가능 여부 확인 → Tier 목록(시각·점수·SHA)과 제출관리 화면 항목의 1:1 대조 → 사용자 결정. 80.890824는 삭제 후 화면에 표시될 합계일 뿐 적격성 인증이 아니다. 다만 Tier 1(외부자료 계보)은 계보 자체가 비적격이므로, 검증 대상 규칙이 무엇이든 삭제가 적격성을 낮추지는 않는다는 점은 유지한다. 삭제의 비용은 표시 총점 하락(81.35→80.89)뿐이다.
4. Codex가 제안한 순서를 채택한다: P3 재가중 계산 독립 검증 → 최종 검증 대상·비적격 제출 목록 확인 → 남은 슬롯 결정. 현재 P3 재학습은 그대로 유지한다.

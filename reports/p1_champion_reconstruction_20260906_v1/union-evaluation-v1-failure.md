# 결론: 결합 점수를 계산하지 않았으며, 평가기 fold 배정의 기술 오류다

트리나 MS-TCN의 성능 실패가 아니다. 봉인된 평가기가 원래 양성 run의 fold 소유권 대신 달력 분기를 사용해, Q3에 속한 10월 119행을 Q4로 배정했다. `chronology()`의 행수 검사가 이를 잡아 성능 열을 읽기 전에 중단했다.

- 새 트리와 원본 MS-TCN metadata의 fold 행수는 각각 Q3 176,738 / Q4 111,124로 동일하다.
- 잘못된 달력 배정만 Q3 176,619 / Q4 111,243이다. 이 상태의 key+fold 비교에서 119/119 불일치가 나왔으며 관측행 결손을 의미하지 않는다.
- 원본 추출 코드의 Q3→Q4 연결 순서와 metadata의 행수를 이용해 **키 열만** 분리하고 원래 length-prefixed key SHA를 재계산했다. 두 fold 모두 정확히 일치했다.
- 평가 label/proposal 값·중간 점수·공식 입력·모델 읽기·추가 fit·CSV·upload는 모두 0이다. 모델 학습과 기존 봉인 파일을 변경하지 않았다.

기술 정정은 원래 fold 소유권과 키 해시를 보존하는 새 ID가 필요하다. 원 v1을 수정하거나 119행을 빼서 점수를 내지 않는다. 상세 근거는 [실패 영수증](union-evaluation-v1-technical-failure.json)에 남겼다.

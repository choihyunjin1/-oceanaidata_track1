## 해석 원칙

- 이번 테스트의 실패는 **정확히 실행한 recipe의 증거**다. 모든 장기 문맥, 수심 정보, 결측 증강, 시계열 모델이 무가치하다는 결론이 아니다.
- 일부 기간 악화나 신뢰구간의 0 포함을 임의의 절대 탈락 조건으로 쓰지 않는다. 성능 크기와 위험을 별도로 기록한다. 반대로 규정·누출·키 정렬·재현성은 낮은 우선순위로 내리지 않는다.
- 약한 reference를 이겼다는 것만으로 최고점 후보라 부르지 않는다. 과거 공식 최고와 최신 규정 적합 후보, 동일 내부 평가 1위를 구분한다.
- 내부 검증에 과거 데이터가 반복 노출됐다는 사실은 남는다. split을 새 이름으로 저장하거나 seed를 바꿔 fresh test라고 부르지 않는다.
- 배포 input은 모델/선택 조건을 고정한 뒤 추론과 키 정렬에만 사용한다. 운영진 원자료, 인터넷상의 가려진 정답, Public membership 추정, 반환 점수 역산 계수는 사용하지 않는다.
- source → 학습 → 저장 모델 → 새 프로세스 예측 경로를 연결한다. 과거 답안 CSV를 모델로 포장하지 않는다. 로컬 후보 준비를 최종 ZIP·공식 채점 완료로 부르지 않는다.

## 기술 문제와 성능 문제 분리

P1 decoder 첫 launch는 연구 runner 경로에서 `run_` 접두사가 빠진 pre-execution 검사 오류로 종료됐다. attempt lock/학습/평가 전이므로 성능 실패가 아니다. 실패 로그를 보존하고 경로 resolver 및 회귀 테스트를 보완한 뒤 같은 모델/데이터/선택 계약의 첫 실제 실행을 진행한다. 기존 screen을 재시작하거나 결과에 따라 임계값을 바꾼 것이 아니다.

P3 source-only prepare 후의 UTF-8 JSON 읽기, CSV 정렬 후 roundtrip 비교, replay를 포함한 runtime 합산은 비모델 QA 보완이다. 최초 prepare code hash와 보완된 train/predict code hash를 구분해 기록한다.

## 다음 연구에 재활용할 단서 — 이번에는 실행하지 않음

1. **P1:** raw always-on decoder F1 0.852792와 inner-selected decoder 0.850291의 차이는 모델 표현력뿐 아니라 선택 절차의 시간 전이가 문제일 가능성을 보여준다. 또한 공식 입력 전 행의 연도별 수심 사전 키가 unknown이다. 후속 연구에서는 배포 train만으로 연도별 사전 의존성을 제거하는 후보를 만들고, 이전 연도만 학습한 검증과 seen-year 검증을 나눌 수 있다. 새 모델·선택 정책은 새 계약으로 평가하며 이번 저장 모델을 덮어쓰거나 official 값을 이용해 fallback을 맞추지 않는다.
2. **P2:** 다른 구조나 실제 수심을 넣는 것보다, 배포 시 발생하는 공개층 연속 결측을 학습에 모사한 것이 이번 비교에서 효과가 있었다. 현재 후보의 공식 결과와 내부 계절별 결과를 별도로 기록하고, 반환 점수에서 보정 계수나 hidden QC 마스크를 풀지 않는다. 전체 평균보다 9~10월의 작은 개선을 함께 보아야 한다.
3. **P3:** 후보의 0.000765m 효과보다 모델 재학습 차이가 클 수 있다. 새 OOF drift를 확인한 뒤, 미세한 혼합 가중치 탐색 전에 재현 분산과 익명 48h context의 표현 일치를 확인하는 것이 우선이다. GPU 예측 저장/재로딩 일치가 GPU 재학습의 bitwise 동일성을 뜻하지 않는다.

## 세션·이전 연구에서 확인한 반복 낭비

전체 대화 전수 감사라고 주장하지 않는다. 현재 스레드의 최근 완료 실행 기록, 저장된 8월31일 자기감사,
9월5일 재구축/제출 영수증과 현재 변경을 대조했다.

1. 과거 선택면의 작은 개선을 독립 일반화 근거처럼 읽는 문제: 단일 result에 retrospective 표기를 유지한다.
2. P3 Ordered/nonsymmetric 조합의75번째 fit 실패와 P1 실행 경로 오류: parameter/schema/path synthetic 검사를 먼저 한다.
3. 같은 규정·과거 결과를 매 감시마다 다시 읽고 장문으로 재작성: 현재 계약과 archive를 분리한다.
4. 모델명만 달라진 같은 가설의 재진입: 데이터/target/split/후처리와 기존 결과를 먼저 대조한다.
5. 새 모델 결과마다 무관한 전체 테스트·설치·CUDA smoke 반복: 변경 관련 검사와 환경 변경 시 검사로 나눈다.

현재 모델 코드 삭제를 보류한 이유도 실제 사용처에 있다. 예를 들어

현재의 새 실험에 안 쓰인다는 이유만으로 지우면 과거 재현 경로를 손상시킨다.

## 검증 루프의 실제 검증

검증 도구는 최초9개 테스트 뒤 독립 리뷰를 받았다. 리뷰에서 발견한 test helper/config 지문 누락,
collect-only 오인 통과, 동시 캐시 임시파일 충돌을 수정했다.
root conftest 생성/변경 검사를 보강한 최종 도구20개 + 정책 회귀2개 = **22개 실제 실행 PASS**, Ruff PASS였다.
JUnit 실행 수0/전부skip/보고서없음, 실패, 검사 도중 source 변경, 손상된 cache는 PASS 재사용 대상이 아니다.
최종 실행에서 실제 pytest 시간은3.56초였다. 과거78개 검사와 범위가 다르므로 속도 개선률로 환산하지 않는다.
Python/패키지/명령/관련 파일 지문이 바뀌면 재실행한다. 설치된 타사 스킬/전역 설정은 변경하지 않았다.

검증 캐시는 선택적이며 만능 의존성 분석기가 아니다. 코드/JSON/YAML/TOML 밖의 fixture,
외부 파일·상태·환경에 의존하는 테스트는 재사용하지 않는다. 원본/OOF/모델/답안의 QA를 대신하지 않는다.
동시 에이전트의 새 소스가 생기면 보수적으로 지문이 바뀐다. 실제 사용 중 한 번의 재호출은
다른 실험 소스 생성으로 캐시 미스가 났으며 이를 재사용 성공이라고 기록하지 않았다.
